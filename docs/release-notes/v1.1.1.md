**SC LAN Patch 1.1.1** behebt zwei Fehler beim LAN-Spiel unter Windows, die
beim ersten Test auf echter Hardware aufgefallen sind: **Beitreten fror ein**,
wenn der Router UPnP kann, und das Spiel **stürzte beim Öffnen von
„Mehrspieler“ gelegentlich ab**. Update dringend empfohlen.

> Die Spieldateien sind **nicht** enthalten. Ihr braucht eine eigene Kopie des
> Spiels. Die Spiel-EXE wird nicht verändert. Für das LAN-Spiel muss der Patch
> auf **allen** Mitspieler-PCs installiert sein.

## Installation

| System | Download | Anleitung |
|---|---|---|
| Windows 10 / 11 | `SC-LANPatch-1.1.1-Windows.zip` | ZIP entpacken → `install.bat` per Rechtsklick „Als Administrator ausführen“ ([Anleitung](https://github.com/bertibertig/StrongholdCrusader-LANPatch/blob/v1.1.1/docs/ANLEITUNG-Windows.md)) |
| Linux (Proton / Wine / Steam) | `SC-LANPatch-1.1.1-Linux.tar.gz` | `./sclan-linux.sh install` → `./sclan-linux.sh start` ([Anleitung](https://github.com/bertibertig/StrongholdCrusader-LANPatch/blob/v1.1.1/docs/ANLEITUNG-Linux.md)) |

Im Spiel: **Mehrspieler → „Internet TCP/IP Connection For DirectPlay“**. Host
klickt **Host**, Mitspieler lassen das **IP-Feld leer** und klicken **Beitreten**.

**Update von 1.0.0 / 1.1.0:** `dplayx.dll` im Spielordner ersetzen – auf
**allen** PCs. Die vorhandene `sclanpatch.ini` kann bleiben: die neuen
Einstellungen sind ohne Eintrag eingeschaltet.

## Behoben

- **Beitreten friert ein (Router mit UPnP).** DirectPlay richtet über UPnP
  eine Portweiterleitung am Router ein und meldet den Mitspielern dann die
  **öffentliche** Adresse des Routers statt der LAN-Adresse. Die meisten
  Heimrouter leiten Verbindungen an die eigene öffentliche Adresse nicht ins
  LAN zurück (kein „NAT-Hairpinning“) – der Beitretende wartet, bis DirectPlay
  aufgibt. Zwei Gegenmittel, beide standardmäßig an:
  - `BlockNATHelp=1`: Der Patch verhindert, dass DirectPlay seinen NAT-Helfer
    lädt. Der Host meldet so seine LAN-Adresse.
  - `HairpinFix=1`: Will DirectPlay trotzdem zur öffentlichen Adresse des
    eigenen Routers verbinden (z. B. weil der Host noch keinen 1.1.1-Patch
    hat), fragt der Patch den Router per UPnP, welcher LAN-PC hinter der
    Weiterleitung steckt, und verbindet direkt dorthin.
- **Absturz beim Öffnen von „Mehrspieler“.** Zwei Threads des Patches haben
  gleichzeitig dieselbe Importtabelle verändert. Je nach Timing stürzte das
  Spiel in `dplayx.dll` ab. Das Patchen läuft jetzt nacheinander und schlägt
  im Fehlerfall mit einer Log-Zeile fehl statt mit einem Absturz.

## Neu im Log (`sclanpatch.log`)

- `game: <exe>` – welche Spiel-EXE den Patch geladen hat.
- `blocked DirectPlay NAT helper (dpnathlp.dll) …`
- `enum: reply address …` – mit `WARNING`, falls ein Host eine nicht-lokale
  Adresse meldet.
- `upnp: …` / `hairpin: … is a UPnP mapping -> connecting to <LAN-IP> instead`

## Bekannte Einschränkungen

- Die Umleitung (`HairpinFix`) braucht einen Router mit UPnP. Ohne UPnP und
  ohne Hairpinning muss der Host den Patch 1.1.1 haben (`BlockNATHelp=1`).
- `BlockNATHelp=1` schaltet DirectPlays automatische Portweiterleitung ab. Wer
  ohne VPN direkt übers Internet spielen will, setzt `BlockNATHelp=0`.
- Unter Linux ist Microsofts DirectPlay im Prefix Pflicht. Wines eigenes kann
  keine Spiele hosten. `sclan-linux.sh install` erledigt das.
- Der erste Suchlauf kann bis zu ~5 Sekunden dauern.
- `DiscoveryPort` muss auf allen PCs gleich sein (Standard 47630).

## Für Entwickler

- `src/upnp.c`: SSDP-Suche nach dem Router (IGD), `GetExternalIPAddress`,
  `GetSpecificPortMappingEntry`; `connect`/`sendto` in `dpwsockx.dll` werden
  über `sclan_hairpin_translate` umgeleitet.
- `src/hooks.c`: `LoadLibrary*` in `dpwsockx.dll` gehookt, um `dpnathlp.dll`
  abzuweisen; `sclan_patch_iat` serialisiert und nutzt `WriteProcessMemory`.
- `tools/dptest.c`: `DPTEST_GUID={…}` testet gegen die Sessions des echten
  Spiels.
